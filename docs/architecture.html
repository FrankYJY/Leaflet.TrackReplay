时间轴对齐的批量数据回放，怎么搭起来的

三张图分别回答三个问题：谁依赖谁、一份数据从哪来、经过谁、到哪去、 增删一个数据集时到底发生了什么。所有标注都对应仓库里的真实模块名与选项名。

蓝 会话 / 身份（跨重建不变的那一层） 橙 时间轴 / 播放（驱动每帧的那一层）

分层总览

从上到下是依赖方向：宿主页面只认识一个门面，门面持有"跨重建不变"的三样东西， 真正的构建器每次数据变化被整体替换，最底下是 Leaflet 与两个可降级的可选插件。

  • 门面公开对象、on()/off() 总线、setTimeZone() / setCalendar() 都在这一层；重建只换内部 handle。
  • 会话级控件数据源面板与多命中搜索由门面创建，不随重建销毁——所以导入列表、展开状态、搜索索引都留得住。
  • 降级可选插件缺失时：轨迹点与背景节点退化为普通 FeatureGroup，图层树退化为扁平 L.control.layers；功能不报错，只是少了聚合与层级树。
  • utils/TimeZone显示时区贯穿时间标签、双击编辑、日界线刻度、节假日查表键——四者永远读同一个 zone 对象。

一条数据的旅程

从"你手里的数据"到"地图上会动的轨迹"只有一条主干；下面那组是并行服务——它们不受每帧驱动， 但决定时间轴怎么读、以及大数据的预览和导出怎么不把页面拖死。

  • 一处转换坐标基准（dataDatum → mapDatum）只在 DataParser 里发生一次，之后所有图层、插值、方位角都在同一坐标系里算。
  • 拆段的触发逐段样式、逐段弹窗、逐点弹窗任一存在，或整条没有基础样式时，才会拆成逐段 Feature；否则整条保留为一个要素。
  • 不变量times 长度 = 坐标点数；speeds / styles / popups = 点数 − 1；pointPopups = 点数。写错长度是静默失败的主要来源。
  • 护栏导入有体量闸、预览有双上限、导出有字符与时间双预算；三者都选择"中止并报告"而不是让页面卡死。

一次 rebuild 的生命周期

增删数据集不是"往地图上加东西"，而是先留住状态、拆掉当前这一代、用合并后的数据重造、再把状态放回去。 这张图就是那四步。

  • 为什么拆得干净每一代 buildReplay 返回自己的 handle（引擎、图层、控件、路由、指示器）；门面只把 handle 换掉，旧的那一代连同它的定时器与监听一起消失。
  • 跨数据集的对象同一 layerPath 的要素在容器里合并，所以"删掉一份数据"后，跨数据集的对象保留剩余部分，独属它的对象整体消失。
  • 空会话没有数据时不构建（没有控件）；第一份数据触发构建；clearDatasets() 回到空态且可继续使用，destroy() 才是整体拆除。

依赖

运行时只有 Leaflet（peer ^1.7）；markercluster 与 Layers.Tree 可选且自动降级。其余一切（导入、预览、搜索、时区、节假日、控件）都是仓库内的自研代码。
